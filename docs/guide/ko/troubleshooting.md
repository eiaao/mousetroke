# 문제 해결

## 제스처가 발동하지 않을 때

먼저 전체 화면이 아닌 일반 브라우저 창에서 간단한 내장 제스처를 시험하세요.

- 트레이/메뉴 막대 메뉴를 확인하세요. Windows에서 **제스처 재개**가 보이면 선택하고, Mac에서 **제스처 일시 정지**가 체크되어 있으면 다시 클릭하세요. 단축키로 엔진이 일시 정지됐다면 **기본 설정 → 일시 정지 / 재개 단축키**를 확인하세요.
- 전체 화면에서 나오세요. 자동 전체 화면 억제는 수동 일시 정지가 꺼져 있어도 마우스 제스처와 가장자리 동작을 모두 멈출 수 있습니다.
- 설정에서 앱을 선택하고 **이 앱에서 제스처 끄기**를 확인하세요. 개별 바인딩의 **켜짐** / **꺼짐** 스위치, **전역 제스처도 함께 사용**, 트리거 버튼과 추가 단계도 확인하세요.
- 버튼을 누른 뒤 바로 움직이고 더 긴 궤적을 그리세요. 기본 설정에서 **움직이지 않고 있을 때 클릭으로 취급하는 시간**과 **획 감도**를 조정하세요.
- 피드백이 없으면 **궤적 표시**와 **그리는 동안 제스처 이름 표시**를 확인하세요. 궤적이 숨겨져 있다고 인식이 꺼진 것은 아닙니다.

Windows에서 입력은 `SendInput`을 사용합니다. Windows UIPI 때문에 일반 권한으로 실행된 인스턴스는 승격된 앱에 키/클릭을 보낼 수 없을 수 있습니다. 먼저 승격되지 않은 앱으로 시험하고, 관리자 창을 제어해야 하면 Mousetroke를 해당 권한으로 실행하세요. 보안 데스크톱으로의 전송은 되지 않습니다.

Mac에서는 설치된 사본의 **손쉬운 사용**을 확인하세요. 설정 화면이 계속 **입력 모니터링**을 요구하면 그것도 허용하세요. 권한 변경이 감지되는 데 몇 초 걸릴 수 있습니다. 그래도 입력이 시작되지 않으면 제공되는 **Mousetroke 재시작**을 사용하세요. 화면 기록은 필요하지 않습니다. 브라우저를 통해 사본을 옮기거나 교체하면 첫 실행 승인이 다시 필요할 수 있습니다.

## SmartScreen이나 Gatekeeper가 첫 실행을 막을 때

Windows: 릴리스 페이지에서 공식 실행 파일을 받고, 체크섬을 확인한 다음, **추가 정보 → 실행**을 사용하세요. Mac: 응용 프로그램에 설치한 다음 **시스템 설정 → 개인정보 보호 및 보안 → 확인 없이 열기**를 사용하세요. 이전 macOS는 **오른쪽 클릭 → 열기**도 지원합니다. 전체 순서는 [설치](getting-started.md)를 참조하세요.

## 애플리케이션이 키를 받지 못할 때

물리 키보드에서 단축키를 시험해 보세요. 애플리케이션이 활성 상태인지 확인하거나 **먼저 커서 아래 창을 앞으로**를 켜세요. 제스처 대상 기본 설정을 확인하고 [올바른 문법](key-sequences.md)을 사용하세요. `^`는 Control이고, `#`는 Mac에서 Command입니다. 앱이 메뉴나 대화 상자를 여는 데 시간이 필요하면 짧은 `{SLEEP 100}`으로 의존하는 단계를 분리하세요.

Mac 키 시퀀스는 마우스/휠 토큰, 미디어/볼륨 키 토큰, Insert, Print Screen, Break와 F21–F24를 건너뜁니다. 미디어/볼륨 동작에는 **미디어와 시스템**을 사용하세요. 지원되지 않는 옵션은 편집기에 표시되며, 로그도 살펴보세요.

Ctrl+Alt+Del은 Windows 보안 주의 시퀀스이므로 일반적인 합성 입력으로 보낼 수 없습니다. 작업 관리자에는 Ctrl+Shift+Esc를, 잠금에는 Win+L을, 로그아웃에는 `shutdown /l`을 사용하세요. 자세한 내용은 [키 보내기 문법](key-sequences.md#ctrlaltdel을-보낼-수-없는-이유)에 있습니다.

## IME 또는 텍스트 출력이 잘못될 때

일반 키 보내기 문자는 임의의 유니코드 텍스트가 아니라 US 키보드 위치를 나타냅니다. 대문자만으로는 Shift가 추가되지 않습니다. Lua `ms.keys(text, true)`는 유니코드 텍스트를 내보내지만 `^`와 `{` 같은 문법 문자는 여전히 해석합니다.

구두점이 많은 텍스트, 라틴 문자가 아닌 텍스트 또는 특이한 IME 처리를 하는 앱에는 [클립보드 붙여넣기·복원 레시피](lua-examples.md#클립보드-텍스트-붙여넣고-복원하기)를 사용하세요. 이 API로 복원하면 텍스트만 보존되고 이미지나 다른 클립보드 형식은 보존되지 않습니다. 일부 앱은 클립보드 복원 전에 더 긴 지연이 필요합니다.

## Lua 오류

코드가 `function ms_action(...) ... end`를 정의하는지 확인하세요. 런타임은 불러오기와 실행 오류를 [런타임 로그](config.md#파일-위치)에 씁니다. **정보 → 로그 열기**로 여세요. 값에는 `ms.log`를, 짧은 화면 확인 지점에는 `ms.show_toast`를 사용하세요. 지원되지 않는 Mac 함수는 경고만 기록하고 `nil`을 반환할 수 있습니다. 없는 값을 성공으로 간주하지 마세요.

Mac 창 검색/상태 호출은 손쉬운 사용 권한이 필요하고, 키 상태 조회는 권한이 없으면 false를 반환합니다. 결과가 없으면 그 권한을 먼저 확인하세요. 앱 간 최상위와 숫자 밝기는 여전히 지원되지 않으며, 내장 밝기 키 동작은 퍼센트를 제공하지 않습니다. 두 플랫폼에서 `ms.get_brightness` / `ms.set_brightness`는 실패 시 nil을 반환합니다.

Lua 할당 제한은 8 MiB입니다. 스크립트 실행 시간 초과는 없으므로 무한 루프를 피하고, 차단 동작은 [Lua 기초](lua-basics.md#런타임과-제한)를 참조하세요.

## 원격 데스크톱과 게임

원격 데스크톱, 가상 머신, 3D/게임 애플리케이션은 같은 마우스 버튼을 끌기에 사용하거나 합성 입력을 다르게 처리할 수 있습니다. [앱별 제외](per-app.md)를 추가하거나 사용하는 동안 일시 정지하세요. 창 모드 게임은 전체 화면 감지가 적용되지 않으므로 명시적 제외가 필요할 수 있습니다. 키 시퀀스 문제와 애플리케이션 입력 처리를 구분하려면 일반 로컬 앱에서 단축키를 시험하세요.

## 버그 신고

**정보 → 피드백 → 열기** 또는 [GitHub Issues](https://github.com/eiaao/mousetroke/issues)를 사용하세요. 앱 버전, OS 버전, 영향받는 애플리케이션, 제스처와 동작, 기대한 결과와 재현 단계를 포함하세요. **정보 → 로그 열기**의 관련 로그와, 유용하다면 최소한으로 내보낸 설정을 첨부하세요. 공유하기 전에 첨부 파일에 개인 텍스트, 창 제목, 경로나 명령 인수가 없는지 확인하세요.

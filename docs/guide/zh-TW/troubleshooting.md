# 常見問題

## 手勢不觸發

先在一般、非全螢幕瀏覽器視窗試一個簡單內建手勢。

- 檢查系統匣／選單列。Windows 顯示「恢復手勢」時點它恢復；Mac 的「暫停手勢」被勾選時，再點一次恢復。也檢查「偏好設定 → 暫停 / 恢復快速鍵」，確認沒有誤按暫停。
- 檢查「偏好設定 → 全螢幕時暫停手勢」和該程式的「全螢幕時」設定。預設全螢幕會暫停滑鼠手勢和觸發角；可為該程式選擇「保持啟用」，或結束全螢幕再試。
- Windows 部分 UWP 視窗由 `ApplicationFrameHost.exe` 託管，特定應用程式的例外規則無法生效；沒有適用於宿主程序的規則時會採用全域設定。
- 在設定中選取程式，確認「使用手勢」已開啟；同時檢查單條手勢的「啟用」／「已停用」、「也使用通用手勢」、觸發按鈕和附加步驟。
- 按下後儘快移動，並畫長一些。可調整偏好設定中的「按住後多久不動視為一般點擊」和「筆畫靈敏度」。
- 沒有視覺回饋時，檢查「顯示軌跡」和「畫的時候顯示手勢名」。隱藏軌跡不等於沒有識別。

Windows 使用 `SendInput`。一般權限啟動的 Mousetroke 可能因為 Windows UIPI 無法向管理員視窗傳送按鍵／點選。先在一般權限程式中測試；確實需要控制管理員視窗時，以對應權限執行 Mousetroke。這不代表能向安全桌面傳送輸入。

Mac 請為該已安裝的應用程式開啟「輔助功能」。引導仍要求「輸入監控」時，也開啟它。權限變更可能需幾秒才被偵測到；仍無法啟動時，用引導提供的「重啟 Mousetroke」。不需要螢幕錄製權限。移動副本或透過瀏覽器重新下載替換後，可能需要再次允許首次開啟。

## 首次開啟被 SmartScreen 或 Gatekeeper 攔截

Windows 從官方發布頁下載並驗證後，選「其他資訊 → 仍要執行」。Mac 安裝到「應用程式」後，到「系統設定 → 隱私權與安全性 → 仍要打開」；較舊系統也可「右鍵 → 打開」。完整流程見[安裝](getting-started.md)。

## 程式收不到按鍵

先用實體鍵盤測試快速鍵。檢查程式是否已啟用，或開啟「先啟用滑鼠下的視窗再傳送」。核對手勢目標設定及[按鍵語法](key-sequences.md)：`^` 是 Control，Mac 的 `#` 才是 Command。程式開啟選單或對話方塊需要時間時，可以在相關步驟之間加短暫的 `{SLEEP 100}`。

Mac 按鍵序列會跳過滑鼠／滾輪、媒體／音量鍵、Insert、Print Screen、Break 和 F21–F24。媒體和音量請使用「媒體與系統」動作。不支援的選項會在編輯器提示，也應檢查日誌。

Ctrl+Alt+Del 屬於 Windows 安全注意序列，普通模擬輸入不能傳送。可用 Ctrl+Shift+Esc 開啟工作管理員，Win+L 鎖定螢幕，或 `shutdown /l` 登出。詳見[按鍵語法](key-sequences.md#為什麼不能傳送-ctrlaltdel)。

## 輸入法或輸出文字不正確

普通按鍵序列字元代表美式鍵盤位置，不能直接表達任意 Unicode 文字。單獨寫大寫字母也不會自動按 Shift。Lua 的 `ms.keys(text, true)` 能輸出 Unicode 文字，但仍會解釋 `^`、`{` 等語法字元。

使用較多標點、非拉丁文字，或以特殊方式處理輸入法的程式，建議使用[剪貼簿貼上並還原範例](lua-examples.md#貼上後還原剪貼簿文字)。這些 API 只能還原文字，不保留圖片等其他剪貼簿格式。部分程式需要延長還原前的等待時間。

## Lua 錯誤

確認程式碼定義了 `function ms_action(...) ... end`。載入和執行錯誤寫入[執行日誌](config.md#檔案位置)，可用「關於 → 開啟日誌」檢視。用 `ms.log` 記錄值，用 `ms.show_toast` 顯示短提示，判斷指令碼走到哪一步。Mac 上未實作的函式可能只記警告並傳回 `nil`，不要把空值當成功。

Mac 視窗查詢／狀態操作需要輔助功能權限，按鍵狀態查詢缺少權限時傳回 false；結果缺失時先檢查該權限。跨應用置頂和數值亮度仍不支援，內建亮度鍵動作不能提供百分比。兩平台的 `ms.get_brightness`／`ms.set_brightness` 失敗均傳回 nil。

Lua 分配記憶體上限為 8 MiB，沒有指令碼執行逾時。避免無限迴圈，阻塞行為見 [Lua 入門](lua-basics.md#執行環境與限制)。

## 遠端桌面與遊戲衝突

遠端桌面、虛擬機器、3D／遊戲程式可能需要同一滑鼠按鈕拖曳，也可能以不同方式處理模擬輸入。可[為該程式停用手勢](per-app.md)，或使用期間暫停。視窗模式遊戲不一定觸發全螢幕偵測，應明確新增排除規則。在一般本機程式測試快速鍵，有助於區分語法問題與應用程式輸入處理問題。

## 報告問題

使用「關於 → 反饋 → 開啟」，或前往 [GitHub Issues](https://github.com/eiaao/mousetroke/issues)。提供程式版本、系統版本、相關應用程式、手勢和動作、預期結果及重現步驟。附上「關於 → 開啟日誌」中的相關日誌，必要時附最小匯出設定。分享前檢查附件中的私密文字、視窗標題、路徑和命令參數。

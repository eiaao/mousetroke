# トラブルシューティング

## ジェスチャーが発動しない

まず、通常の（フルスクリーンでない）ブラウザーウィンドウで、単純な内蔵ジェスチャーを試してください。

- トレイ／メニューバーのメニューを確認します。Windows では**ジェスチャを再開**があれば選び、Mac では**ジェスチャを一時停止**にチェックが付いていればもう一度クリックします。ショートカットでエンジンが一時停止された場合は、**環境設定 → 一時停止 / 再開のショートカット**を確認してください。
- フルスクリーンを解除します。手動の一時停止がオフでも、フルスクリーンの自動抑止はマウスジェスチャーと画面の端の動作を止めることがあります。
- 設定でアプリを選び、**このアプリでジェスチャをオフ**になっていないか確認します。個々の割り当ての**オン**／**オフ**スイッチ、**共通ジェスチャも使う**、トリガーボタン、追加ステップも確認してください。
- ボタンを押したらすぐに動かし、長めの軌跡を描きます。**押したまま動かないとクリック扱いにする時間**と**ストロークの感度**は、環境設定で調整します。
- フィードバックが表示されない場合は、**軌跡を表示**と**描いている間はジェスチャ名を表示**を確認します。軌跡が非表示でも、認識がオフということではありません。

Windows では、入力に `SendInput` を使います。通常の権限で起動したインスタンスは、Windows UIPI のため、管理者権限のアプリへキーやクリックを送れないことがあります。まず管理者権限でないアプリで試してください。管理者ウィンドウを操作する必要がある場合は、Mousetroke を同じ権限で起動します。これはセキュアデスクトップへの送信を可能にするものではありません。

Mac では、インストール済みのコピーに対する**アクセシビリティ**を確認してください。セットアップが**入力監視**を求め続ける場合は、それも許可します。権限の変更が検出されるまで数秒かかることがあります。入力が始まらないままのときは、案内があれば**Mousetroke を再起動**を使ってください。画面収録は不要です。ブラウザー経由でコピーを移動や置き換えをすると、初回オープンの承認が再度必要になることがあります。

## SmartScreen や Gatekeeper に初回起動をブロックされる

Windows：リリースページから公式の実行ファイルを入手し、チェックサムを確認してから、**詳細情報 → 実行**を使ってください。Mac：アプリケーションへインストールしてから、**システム設定 → プライバシーとセキュリティ → このまま開く**を使います。古い macOS では**右クリック → 開く**も使えます。一連の手順は[インストール](getting-started.md)を参照してください。

## アプリがキーを受け取らない

まず実際のキーボードでショートカットを試してください。アプリがアクティブか確認するか、**先にカーソル下のウィンドウを前面にしてから送る**を有効にします。ジェスチャーの対象設定を確認し、[正しい構文](key-sequences.md)を使います。`^` は Control で、Mac では `#` が Command です。アプリがメニューやダイアログを開くのに時間がかかる場合は、依存するステップの間に短い `{SLEEP 100}` を入れてください。

Mac のキー列では、マウス／ホイールトークン、メディア／音量キートークン、Insert、Print Screen、Break、F21～F24 をスキップします。メディア／音量の動作には**メディアとシステム**を使ってください。非対応の項目はエディターで表示され、ログも確認できます。

Ctrl+Alt+Del は Windows の Secure Attention Sequence で、通常の合成入力として送信できません。タスク マネージャーには Ctrl+Shift+Esc、ロックには Win+L、サインアウトには `shutdown /l` を使ってください。詳しくは[キー送信の構文](key-sequences.md#ctrlaltdel-を送れない理由)にあります。

## IME やテキスト出力が正しくない

通常のキー送信の文字は、任意の Unicode テキストではなく US キーボードの位置を表します。大文字にするだけでは Shift は付きません。Lua の `ms.keys(text, true)` は Unicode テキストを出力しますが、`^` や `{` などの構文文字は引き続き解釈されます。

記号が多いテキスト、非ラテン文字、IME の処理が特殊なアプリには、[クリップボードで貼り付けて戻す例](lua-examples.md#クリップボードのテキストを貼り付けて戻す)を使ってください。これらの API での復元はテキストだけで、画像などの他のクリップボード形式は保持されません。復元の前に長い待機が必要なアプリもあります。

## Lua エラー

コードが `function ms_action(...) ... end` を定義していることを確認してください。ランタイムは読み込みエラーと実行エラーを[ランタイムログ](config.md#ファイルの場所)に書き込みます。**このアプリについて → ログを開く**で開けます。値の確認には `ms.log` を、簡単な画面上のチェックポイントには `ms.show_toast` を使います。Mac で対応していない関数は警告をログに記録して `nil` を返すだけのことがあるため、値がないことを成功と扱わないでください。

Mac のウィンドウ検索と状態の呼び出しにはアクセシビリティ権限が必要で、キー状態の照会は権限がないと false を返します。結果が得られない場合は、まずその権限を確認してください。アプリをまたぐ最前面固定と数値の明るさは引き続き非対応で、内蔵の明るさキーの動作はパーセントを返しません。`ms.get_brightness` と `ms.set_brightness` は、両プラットフォームで失敗時に nil を返します。

Lua の割り当て上限は 8 MiB です。スクリプトの実行タイムアウトはないため、無限ループを避け、ブロックの挙動は [Lua 入門](lua-basics.md#実行環境と制限)を参照してください。

## リモートデスクトップとゲーム

リモートデスクトップ、仮想マシン、3D／ゲームアプリは、ドラッグに同じマウスボタンを使うか、合成入力の扱いが異なることがあります。[アプリごとの除外](per-app.md)を追加するか、使用中は一時停止してください。ウィンドウモードのゲームはフルスクリーン検出の対象外のため、明示的な除外が必要なことがあります。キー列の問題とアプリの入力処理を切り分けるには、通常のローカルアプリでショートカットを試してください。

## バグを報告する

**このアプリについて → フィードバック → 開く**か [GitHub Issues](https://github.com/eiaao/mousetroke/issues) を使ってください。アプリのバージョン、OS のバージョン、対象のアプリ、ジェスチャーと動作、期待した結果、再現手順を書いてください。役立つ場合は、**このアプリについて → ログを開く**の該当するログと、最小限に書き出した設定を添付します。共有する前に、添付ファイルに個人的なテキスト、ウィンドウタイトル、パス、コマンド引数が含まれていないか確認してください。

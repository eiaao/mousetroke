# 配置、备份与更新

## 文件位置

| 文件 | Windows | Mac |
|---|---|---|
| 配置 | `%APPDATA%\mousetroke\config.json` | `~/Library/Application Support/mousetroke/config.json` |
| 运行日志 | `%APPDATA%\mousetroke\mousetroke.log` | `~/Library/Logs/mousetroke/mousetroke.log` |

日志超过 1 MB 后轮转为 `mousetroke.log.old`。“关于 → 文件位置”显示实际路径，“打开文件夹”打开配置目录，“打开日志”打开运行日志。“导入与导出”中，Windows 的“在资源管理器中显示”或 Mac 的“在 Finder 中显示”可定位配置。

## 导出、导入与恢复

“导入与导出 → Mousetroke 配置文件”中点“导出…”，保存 JSON 备份。“从文件导入…”读取 Mousetroke 配置 JSON，替换包含偏好设置的整份当前配置，不会将文件中的绑定合并进来。这个流程没有原生配置合并选项。设置窗口仍打开时，可用 Windows 的 Ctrl+Z 或 Mac 的 ⌘+Z 撤销导入。

手改 JSON 前先导出备份。直接恢复文件时，退出引擎并关闭设置，用备份替换 `config.json`，再打开 Mousetroke。恢复期间保持设置关闭，避免自动保存覆盖刚恢复的文件。

## 热加载与重置

引擎根据文件时间戳检测配置变化。Windows 约每秒检查一次，Mac 在每两秒调度的维护分支中检查。画手势过程中收到的修改，会在捕获结束后应用。JSON 无效时保留此前生效的配置，并在日志记录错误。

当前设置界面没有恢复默认按钮。需要重新使用内置配置时，退出 Mousetroke 并关闭设置，备份后移除或重命名 `config.json`，再打开。文件不存在才会从统一默认配置初始化，预置动作按当前平台执行。损坏文件会原样保留：启动时仅在内存使用默认值，设置程序拒绝覆盖它。恢复或重命名该文件后才能继续保存。

已有版本 1 的配置仍可读取，启动时不会自动改写。保存含预置动作的配置时版本升为 2；首次用版本 2 覆盖版本 1 文件之前，会在旁边创建 `config.v1.bak.json`，保留原始字节，已有备份不会被覆盖。不认识的动作类型或预置 ID 在保存时保留，执行时跳过。

## 更新

“偏好设置 → 自动检查更新”默认开启，每天向 GitHub 检查一次。关闭即可停止自动检查。也可在“关于 → 检查更新”手动检查，用“更新内容”查看说明。菜单中的新版本入口同样会打开关于页面。

Windows 点“立即更新”后下载程序，校验 SHA-256，替换并重启。也可用“打开下载页”手动安装。

Mac 点“立即更新”后下载 DMG，校验 SHA-256、应用身份、版本和签名要求，替换应用并重启。关闭后旧副本进入废纸篓，替换或重启交接失败会恢复旧副本。目录不可写或更新失败时可用“手动下载”。应用内更新避免再次触发浏览器下载的隔离提示，并保留权限对应的安装身份。重新用浏览器下载可能需要再点“仍要打开”。

## 卸载

Windows：在偏好设置关闭“开机时自动启用手势”，从托盘“退出”，关闭设置，再删除程序文件；不再需要设置和日志时也可删除 `%APPDATA%\mousetroke`。

Mac：从菜单栏“退出”，关闭设置，删除 `Mousetroke.app`。需要清理数据时，删除 `~/Library/Application Support/mousetroke` 和 `~/Library/Logs/mousetroke`，并从系统设置登录项中移除 Mousetroke。可能重装时请保留导出备份。

配置报错或找不到日志时，见[常见问题](troubleshooting.md)。

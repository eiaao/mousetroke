# Mac 权限与输入恢复实施计划

**目标：** 引擎自行请求 TCC 权限，授权后自动恢复，撤权或反复超时时不阻塞鼠标。

**架构：** 使用 NSDistributedNotificationCenter 的 bundle 专属通知，object 携带目标 PID，主线程收件后唤醒现有计时器。禁用回调只记录事件并保持关闭，下一拍检查权限、执行纯决策函数；覆盖层和日志副作用延后执行。

**技术栈：** Rust、objc2、React、TypeScript。

**规格：** 本次用户任务；仅一个新提交、不推送，中文注释、新文案覆盖十种语言。

## 实施与验收

- [x] 引擎控制通知替代 restart-request 轮询，同时迁移退出请求；授权请求仅在无引擎时回退设置进程。
- [x] 输入监控请求附带一次 listen-only tap 注册；正常轮询尝试安装并信任成功 tap，避免负预检缓存。
- [x] 引导在两项权限已授予但 tap 未就绪时自动重启一次；延迟提供手动重启，验证失败、关闭与恢复路径。
- [x] 纯决策覆盖撤权、用户禁用、30 秒内第二次超时、边界与恢复；故障移除两个 tap、取消捕获、暂停、更新菜单与快照。
- [x] 审计回调；将 AppKit/Core Animation 绘制与日志队列发送移至计时器，保留有界缓存与同步拦截判断。
- [x] macOS 交叉 check 与 clippy -D warnings、Windows workspace tests、UI test/typecheck/build、i18n lint、打包测试；记录 Mac mini 验收步骤。

Windows 侧检查均通过。真实 TCC／通知时延／鼠标手感仍需按 `docs/MAC-PERMISSIONS.md` 在 Mac mini 验收。

## 审查重点

1. 通知指定旧 PID 时不得控制新引擎，空闲引擎也须在约 0.3 秒响应。
2. 预检负缓存不得否认成功安装的 tap；反复超时不得每两秒重新武装。
3. 自动重启只做一次，重启期间暂时无快照不得提前判为成功。
4. 故障暂停恢复时保留用户原来的暂停选择。
5. 输入回调不能发送 AX IPC、写盘、等待共享锁或调用窗口显示／文字测量。
